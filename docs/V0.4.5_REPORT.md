# Agent Autoloop v0.4.5 本地验收报告

基线为 `8266740`。本轮修改任务工作台、相关只读查询和测试。

## 项目绑定

历史页以 Run 的初始规则版本和触发事件确认 `projectId` 与 `projectScope`。当前项目的两个值都匹配时，工作台选择该项目，同步侧栏和输入框，并重新校验执行方案。无法确认、已移除或目录变更时，目标项目留空，必须主动选择。页面标题显示原任务项目，输入框旁显示下一项独立任务的目标。浏览器提交时附上目录身份，服务端在派发前校验，拒绝加载页面后发生的规则目录变化。

## 审批与后续轮次

`GET /api/runs/:id/why?view=router-chain` 在原会话与同源检查之后，沿原始 Run → 审批 Card → `answer_event` → `run_events` 读取后续 Run。按事实序号应用变更和移除，合并重试时跟踪幸存的关联。页面汇总各分支，保留审批入口和原有轮次详情。只有各分支都结束且没有未处理或待核对的审批，才显示整项任务结束。最终摘要来自各末端轮次，初始摘要在执行过程内可查。

## 代次与异常恢复

状态序号回退或中台连接身份变化会开启新代次。旧历史、分页、提交结果和项目选中缓存依代次失效，异步请求取消或忽略。历史响应同时校验打开任务的一次导航，快速切换、前进、后退及刷新不会沿用另一任务的绑定。普通断线重连保留数据代次。未提交的输入保留。普通请求失败可按原 UUID 重试。代次切换时仍未确认的请求显示结果未知，用户核对后才可清空草稿并继续。对已有回执的网页请求重试，服务端还会核对原外部事件号和当前中台记录。

## 已知限制

- 一次查询最多核对 32 个轮次。缺少后续事实、读不到后续轮次或达到上限时，显示待核对。未通过审批产生的独立事件或定时任务不纳入执行链路。
- 数据代次由已观测的序号回退或连接身份变化识别。同地址、同凭据的数据库若被替换，且新序号在首次观测时已不低于旧序号，现有 Hub 接口没有足够的信息可靠识别这次替换。
- 未确认提交提醒和草稿保留在当前打开的网页内。页面关闭或手动刷新前，应先通过轮次或事件核对结果。
